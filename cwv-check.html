Core Web Vitals / PageSpeed 公開前チェッカー

LP・コーポレート・WordPress を公開／改修する前に、LCP・INP・CLSと画像・フォント・第三者スクリプトのよくある落ちどころを自分で潰します。処理はブラウザ内のみ（送信なし）。PageSpeed Insights / CrUX の公式判定の代替ではなく、受託前の自己点検用です。

1. LCP（Largest Contentful Paint）

LCP候補画像に fetchpriority="high" または preload を付けている（または不要と確認済み）
ヒーロー画像は WebP/AVIF 等に圧縮し、表示幅以上の巨大PNG/JPEGを避けている
画像／静的アセットが CDN または近いオリジンから配信されている
ファーストビューの自動カルーセル／巨大スライダーを止めた、または遅延読込にした
TTFB が遅い原因（安い共有サーバ・未キャッシュ・重いプラグイン）を疑って切り分けた

2. INP（Interaction to Next Paint）

クリック／タップ時に重い同期 JS（巨大メニュー・全商品フィルタ・チャット起動）をメインスレッドで一気に動かしていない
チャット・ヒートマップ・MA・広告タグは同意後またはアイドル後に読み込む方針にした
使っていない jQuery プラグイン／レガシースライダーを外した、または更新した
実機モバイルでメニュー開閉・フォーム入力・カート追加を触って「固まる」箇所をメモした

3. CLS（Cumulative Layout Shift）

画像・iframe・動画に width/height または aspect-ratio を付け、枠を先に確保している
Webフォントは font-display: swap（または optional）で、FOITでレイアウトが跳ねない
遅延挿入のクッキーバナー／お知らせバー／広告枠が上から押し下げない（予約スペース or オーバーレイ）
広告枠の高さを固定し、読み込み後にコンテンツがズレない

4. 画像・フォント・キャッシュ

ファーストビュー以外の画像は lazy-load（LCP画像は lazy にしない）
srcset / sizes でモバイルに過剰解像度を送っていない
日本語 Web フォントはサブセット化、またはシステムフォント優先で必要箇所だけ読み込む
静的アセットに長期キャッシュ（ハッシュ付きファイル名）を付けている
未使用 CSS/JS の削除、またはクリティカルCSSの分離を検討した

5. WordPress / プラグイン特有（該当時）

WordPress ではない／該当なし
ページキャッシュ（またはホストのエッジキャッシュ）が有効
画像最適化プラグイン or CDN画像変換を1系統に統一（二重最適化を避けた）
使っていないプラグイン／ページビルダーの余分なアセットを無効化した
管理画面用スクリプトがフロントに漏れていない

参考：web.dev Core Web Vitals（LCP・INP・CLS のしきい値の考え方）、PageSpeed Insights ヘルプ。数値の合否は実測（フィールド優先）で確認してください。このページは診断代行ではなく自己点検用です。
